Manual verification in a block explorer

  1. Open each transaction by hash and record its chain, status, block number and UTC timestamp.
  2. Check the authorization transaction's type and its list of signed authorizations.
  3. Compare block order; a later block establishes ordering but not the source of the signatures.
  4. Review transfer event logs in the second transaction. Distinguish log events from net balances and the identities of controlling parties.
  5. For account-code history, use a trusted archival Ethereum RPC provider when necessary.

Reproducing selected fields with code

The repository includes a read-only Python verifier and a reproduction guide. The script reads eth_getTransactionByHash and eth_getTransactionReceipt and checks the Ethereum chain ID. It cannot independently reconstruct every cross-chain transfer, measure a dollar loss or prove the initial compromise.

Evidence classification

Directly observable: block, transaction envelope, receipt, account code at a given block. Attributed reporting: wallet ownership labels, operational disclosures and law-enforcement assessments. Unresolved: operator identity, full intrusion chain and how authorization signatures were generated.

Research handling

Keep complete hashes in exported notes, record the provider and time of collection, and avoid relying on screenshots alone. Data snapshots can differ across services; reproducibility depends on chain identity and exact block references. See the authorization mechanism and the incident timeline.
